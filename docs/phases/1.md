# Phase 1 — Project skeleton, cached fetcher, Wikidata disambiguation, search + confirm screens

Builder note, 2026-10-20.

## What was built

**Skeleton.** Next.js 15.5 (App Router) + TypeScript strict, React 19, plain CSS (system font stack, light/dark via `prefers-color-scheme`). Scripts: `dev`, `build`, `start`, `lint` (ESLint 9, `next/core-web-vitals` + `next/typescript`), `typecheck` (`tsc --noEmit`), `test` (Vitest), `test:e2e` (Playwright), `record:wikidata` (fixture recorder). `.env.example` lists `ANTHROPIC_API_KEY`, `WAYBACK_RATE_LIMIT_MS`, `GR_DB_PATH`, `GR_OFFLINE_FIXTURES`. `.gitignore` covers `node_modules`, `.next`, `*.db` (+ WAL/SHM), `data/`, `test-results`, `playwright-report`.

**Database (`src/lib/db/`).** Drizzle + better-sqlite3 (ADR-005). `schema.ts` defines `fetch_cache (url PK, status, body, content_type, fetched_at, source)`, `runs` (incl. `progress` JSON for Phase 2), `reports`, `signals`. Migration choice: an idempotent `CREATE TABLE IF NOT EXISTS` bootstrap (`BOOTSTRAP_SQL`) applied by `openDb()` every time a database is opened; `tests/unit/db/schema.test.ts` asserts the bootstrap columns equal the Drizzle table columns, so the two cannot drift. WAL mode. `getDb()` honours `GR_DB_PATH` (default `data/greenwash.db`). `client.ts` is the only file importing the driver. Repos: `FetchCacheRepo`, `RunsRepo`. Tests use a temp DB file per suite.

**Fetch layer (`src/lib/fetch/`).**
- `Fetcher` interface → `FetchResult { url, status, body, contentType, fetchedAt, source: network|cache|fixture }`.
- `UndiciFetcher`: descriptive User-Agent, 15 s timeout, redirect interceptor, `EnvHttpProxyAgent` (honours `HTTPS_PROXY`), retries on 429/502/503/504 and network errors, max 3 tries total, waits `Retry-After` (seconds or HTTP date, capped at 60 s) else exponential backoff; exhausted ⇒ `FetchError` carrying the status.
- `CachedFetcher(inner, repo, ttl)`: serves from SQLite with the original `fetched_at`; caches only definitive answers (not 5xx / 429).
- `RateLimitedFetcher` + `RateLimiter(perHostMs, { hostMinimums })`: slots reserved synchronously per host; `web.archive.org` minimum 1000 ms wired in `services.ts`.
- `robots.ts`: RFC 9309 parser (groups, Allow/Disallow, `*` and `$`, longest match, most specific user-agent), `RobotsChecker` (one robots.txt fetch per origin, missing ⇒ allow), `RobotsGuardedFetcher` (throws `RobotsDisallowedError`), `skippedFromError()` ⇒ `skipped: robots.txt disallows <url>`.
- `FixtureFetcher(rootDir, map)`: URL → fixture file, unknown/missing ⇒ 404, never network, cannot escape the root.
- `src/lib/services.ts` wires everything: `GR_OFFLINE_FIXTURES=1` ⇒ `FixtureFetcher`; otherwise `CachedFetcher(RateLimitedFetcher(UndiciFetcher))` with TTL `GR_CACHE_TTL_HOURS` (default 168).

**Wikidata (`src/lib/wikidata/`).** `search.ts` (`wbsearchentities`, limit 7, English; error payloads such as `cirrussearch-too-busy-error` raise `WikidataError`), `entities.ts` (`wbgetentities` in three cached calls: the hits with labels/descriptions/aliases/claims; their P31 classes with claims for one level of P279; labels for P452/P17/P749 items; English label with `mul` fallback — Fairphone has only a `mul` label), extracting P856 website (preferred rank first), P749 parent, P452 industry, P17 country, P154 logo (Commons URL), P31. `rank.ts` implements the brief's rule: an item is eligible only if it is an instance of a brand/company/organisation class or of a direct subclass of one (`config/wikidata.json`, fictional classes excluded); confident ⇔ exactly one eligible item has an exact normalised-name match (label or alias, legal suffixes / diacritics / punctuation stripped) **and** a website; otherwise up to 3 candidates ranked by a documented score. `disambiguate.ts` combines them; `candidateById()` re-resolves the confirmed entity server side (from cache) so client-sent fields are never trusted.

**Fixtures (`fixtures/wikidata/`, 21 files).** Real Wikidata responses recorded 2026-10-20 with `npm run record:wikidata` (see `fixtures/wikidata/README.md`): `patagonia` (confident: Patagonia, Inc., Q1660552, patagonia.com), `acme` (no eligible company ⇒ URL fallback), `continental` (two plausible companies, Continental AG and United Airlines ⇒ cards, none confident), and the two other fixture brands provisionally chosen for Phase 2, `fairphone` (electronics, confident Q5019402) and `oatly` (food, confident Oatly AB Q10605824). Phase 2 confirms the brand choice in `fixtures/brands/README.md`.

**Screens.**
- `/`: one "Brand name" search input; Enter submits (plain GET form to `/confirm?q=`, works without JS).
- `/confirm?q=`: confident ⇒ creates the run and redirects to `/analyse/[runId]`; otherwise up to 3 cards "Did you mean **Name** — description, country, host?" with **Confirm** (server action, re-resolves the entity) and **Not this one** (link adding the id to `reject=`; no JS needed). No candidates, or all rejected, or lookup failure ⇒ URL-paste fallback (validated/normalised server side; invalid input is refused with an inline error and no run).
- `/analyse/[runId]`: placeholder showing brand, website host and Wikidata id.
- `/api/runs/count`: test-only route (404 unless `GR_OFFLINE_FIXTURES=1` or `GR_TEST_ROUTES=1`).
- All copy in `src/lib/copy/wording.ts` (started now; Phase 3 adds signal templates and the forbidden-word test).

## Skipped / deviations, and why

- **Confirm card for Patagonia is not shown**, because the recorded fixture is a confident match and the brief says to proceed; criterion 1.6 allows this ("or auto-proceeds if confident"). If a card were shown it would read the Wikidata description ("American clothing company"), not "outdoor apparel": Patagonia's P452 industry on Wikidata is "retail", so the card prefers the item description and falls back to the industry. The card path is exercised by "continental".
- **Logo (P154)** is extracted and stored on the run's entity JSON but not rendered: rendering would load an image from Wikimedia Commons, which breaks the offline test mode and adds nothing to the evidence. Revisit in Phase 8 if wanted.
- **Robots.txt is not applied to Wikidata API calls**: robots.txt governs crawling; the Wikidata API is an API with its own usage policy (descriptive UA, Retry-After, caching), which we follow. `RobotsGuardedFetcher` is ready for brand pages in Phase 2.
- **Auto-proceed creates the run during the GET render of `/confirm`.** Acceptable because nothing links to `/confirm` with prefetch; the confirm/URL paths use POST server actions.
- **Playwright runs `next dev`** (port 3123, fresh `test-results/e2e.db`, `GR_OFFLINE_FIXTURES=1`), one worker so the run-count assertions are not raced. The pinned `@playwright/test@1.56.1` matches the preinstalled `chromium-1194`, so no `executablePath` override is needed. The iPhone 12 profile runs in Chromium (WebKit is not installed).
- Wikidata rate-limited the build container (429, `Retry-After` up to ~50 s, plus `cirrussearch-too-busy-error`); the recorder retries politely. This is a build-env fact for `docs/LIMITATIONS.md` (Phase 9).

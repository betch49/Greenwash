# Phase 4 — Wayback snapshots, diff, retraction detector (A), timeline

Builder note, 2026-10-20.

## Built

- **`src/lib/wayback/cdx.ts`** — `cdxUrl(page, now)` builds the brief's query exactly (`url=<page, percent-encoded>&output=json&filter=statuscode:200&collapse=timestamp:4&from=<year-8>`); `parseCdx` reads the header row + data rows by column name; `pickYearly` keeps one capture per calendar year (newest of each year) for the last 8 years (2019–2026 today); `listSnapshots`; `waybackIntervalMs` (WAYBACK_RATE_LIMIT_MS can raise the spacing, never below 1000 ms); `WaybackUnavailableError` for network errors, 429, 5xx and non-JSON 200 answers. Parameters in `config/wayback.json` (`years: 8`, `maxPages: 3`, `sameClaimSimilarity: 0.8`, `contextSentences: 2`, `minIntervalMs: 1000`).
- **`snapshot.ts`** — `https://web.archive.org/web/<ts>id_/<url>`, `visibleText` on the raw page (nav/header/footer stripped as for live pages), `fetchedAt` kept from the cache. `waybackAwareTtl`: the shared `CachedFetcher` now takes a per-URL TTL; `id_` snapshots never expire, everything else keeps `GR_CACHE_TTL_HOURS`.
- **`diff.ts`** — `diffSnapshots` / `diffSentences`: `diffArrays` (package `diff@8`, added) over the Phase 3 sentence splitter's output, sentences compared after normalising case, spaces, quotes and closing punctuation ⇒ `{ removed, added, from, to }`. `similarity`: Sørensen–Dice over character bigrams of the normalised sentences.
- **`retraction.ts`** — `detectRetractions(snapshots, { brand })`: for each consecutive pair, every removed sentence that a Phase 3 rule matches (`classify`, same next-sentence and brand context) and that has no sentence ≥ 0.8 similar in the later snapshot ⇒ `Signal{ axis: 'track', kind: 'claim.removed', source_url: earlier id_ URL, snapshot_date, fetched_at, excerpt: the sentence, llm_used: false }` + a `DiffCandidate` (`classification: 'unclassified'`, context before/after in the earlier copy, nearest sentence and its similarity in the later copy) for Phase 7. Same claim removed twice (after a restore) ⇒ one signal. Builds `TimelineEntry { year, snapshot_url, claims_present, claims_removed }` per snapshot, plus `page_url`, `snapshot_date` and `previous_year` (needed to print "between X and Y" and to group by page).
- **Pipeline step** `src/lib/pipeline/steps/wayback.ts`, label `Pulling <y1>–<y2> snapshots` (`steps.wayback`), placed in the brief's order: discover → fetch current pages → **Wayback** → claim language → evidence. Targets: robots-disallowed sustainability-type pages first (brief Section 8 / the Phase 2 carry-forward: we cannot fetch them live, so we read their history), then fetched sustainability-type pages, at most 3. Uses `ctx.apiFetcher` (the cached, rate-limited fetcher without the robots guard; ADR-010: Wayback API endpoints only); brand pages still only go through `ctx.pageFetcher`. Failure handling:
  - network error / 429 / 5xx / non-JSON CDX ⇒ stop at once, `skipped: Wayback unreachable (<status>)`, keep what was found before, add a could-not-check line; the run continues;
  - CDX non-200 for **every** target ⇒ same skip (a valid CDX query never answers 404, so this is the archive not serving us); for only some targets ⇒ could-not-check line per page;
  - `[]` ⇒ could-not-check "no archived snapshot from 2019–2026"; one snapshot only ⇒ could-not-check "no change over time could be checked"; a 404 snapshot ⇒ a `skipped: HTTP 404 for <id_ url>` progress line.
- **Persistence and UI** — new table `run_timeline (run_id PK, data JSON)` + `RunTimelineRepo`; `RunView.timeline`; a minimal "Timeline of archived claims" section on `/analyse/[runId]` (the placeholder report page until Phase 8): one list per page, one row per archived copy linking to its `id_` URL, claim count, and "claim removed between 2021 and 2024: “…”" lines. All strings in `wording.ts`; forbidden-word test green.
- **Rate limit wiring** — `buildRateLimiter(env)` in `services.ts` (web.archive.org minimum from `waybackIntervalMs`), used by `buildFetcher`.
- **Fixtures (ADR-011)** — no real snapshot could be recorded (below), so both histories are for **fictional** brands on `.example` domains, every file marked `synthetic fixture … web.archive.org never served it`:
  - `northwind/` `/our-footprint/`: 2020, 2021, 2024, 2025 copies; "Every Northwind jacket is climate neutral…" present in 2020–2021, absent in 2024–2025; rest largely unchanged (yearly figures, a nav item, promo bar). Empty CDX answers for the other three pages the step looks up (including the robots-disallowed archive page).
  - new fictional `quillmoor/` (Quillmoor Foods Ltd., `www.quillmoor-foods.example`, food, no Wikidata id): robots, home, `/sustainability`, and a 2020/2022 table layout → 2025 card redesign of the same three claims (sentence → heading, "We're" → "We are", reordered).
  - `manifest.json` gains `wayback: { "<page url>": "<page-slug>" }`; `loadBrandFixtures` serves `cdx/<page-slug>.json` and `snapshots/<page-slug>/<YYYYMMDD>.html` for the matching web.archive.org URLs, so offline mode and the tests go through the real CDX/`id_` code path.
  - Guard test extended: Wayback page URLs and CDX `original`s of synthetic fixtures are on reserved TLDs; every CDX row has its snapshot file; a real fixture's snapshot must start with `<!-- real capture: `, a synthetic one with `<!-- synthetic fixture`; no stray snapshot directories.
- **Docs** — METHODOLOGY Section 6 (archived claims: pages, snapshots, diff, removal rule, signal, timeline, examples, skip path; later sections renumbered); `docs/LIMITATIONS.md` created (Wayback unreachable, fixture consequence, coverage limits); `fixtures/brands/README.md` (Quillmoor, Wayback layout and expected results); `docs/LATER.md` (diff newest snapshot vs live page; record real-brand histories).

## Director review

Round 1 of 3, 2026-10-20. Run by the director: `npm run lint` clean, `npm run typecheck` clean, `npm test` 237/237 (30 files), `npm run test:e2e` 17/17 (servers stopped afterwards). Re-plans used in the run: 0/2.

**Criteria.** 4.1–4.7 all have the named test and all pass. 4.1: the URL is asserted character-for-character against the brief's query (`from=<year-8>` as PLAN asks; the extra year is filtered by `pickYearly`), the header-row + data-rows JSON shape is read by column name. 4.2: `id_` URL asserted, two fetches hit the inner fetcher once, snapshot TTL infinite. 4.3: fake-timer test shows ≥ 1000 ms spacing on `web.archive.org` with `WAYBACK_RATE_LIMIT_MS=100`. 4.4/4.5: Northwind gives exactly one `claim.removed` with `snapshot_date` 2021-03-15 and an `id_` receipt; Quillmoor gives zero. 4.6: reset / 429 / 503 / 404-for-all ⇒ `skipped: Wayback unreachable (…)`, next step still runs. 4.7: the placeholder report shows "claim removed between 2021 and 2024" with the sentence and four `id_`-linked rows.

**Judgement on the points the orchestrator asked about.**

(a) **Real clock in e2e — yes, a time bomb.** The server's `ctx.now()` is `new Date()`; `tests/e2e/timeline.spec.ts` asserts 4 Northwind rows and 3 Quillmoor rows. From 2027-01-01 the 2020 captures leave the 8-year window (4 → 3, 3 → 2) and both tests fail; from 2028-01-01 the 2021 capture leaves and the "claim removed between 2021 and 2024" line disappears. PLAN.md requires a suite that is executable with no human input, and Section 10's "Playwright flow passes" would silently become false in 14 months. The builder flagged it honestly; it still has to be fixed (rework item 1). Unit tests already pin the clock and are fine.

(b) **Live Wayback untested, but the recorded-format path is.** `fixtures/brands/*/cdx/*.json` use the real CDX `output=json` shape (header `urlkey, timestamp, original, mimetype, statuscode, digest, length`, then rows), `[]` for no captures; the fixture fetcher serves them for the exact CDX URL the code builds and serves snapshots for the exact `…/web/<ts>id_/<original>` URL, so the e2e and the retraction tests go through the real `cdx.ts`/`snapshot.ts` code. The `original` from the CDX row (not the page URL we asked for) is used to build the `id_` URL, which is what the live archive needs. Rate limit proven with fake timers. Accepted; the live run stays in `docs/LIMITATIONS.md` and `docs/LATER.md`, and will be the first thing to run in the Section 10 check if the network allows.

(c) **Newest snapshot not compared with the live page.** Deliverable 3 asked for consecutive snapshots only, so this is not a Phase 4 defect, but it is a real hole in differentiator A: `collapse=timestamp:4` returns the *first* capture of each year, so a claim dropped any time after January of the current year is invisible until next year. The live page text is already in `ctx.pages`; treating it as the final element of the sequence reuses `detectRetractions` unchanged. Moved into Phase 7 (ADR-017), where diff candidates are classified anyway. **Robots-blocked pages' archived text is not scored on the claims axis** — decided to keep it that way (ADR-016): an archived copy can be years old, and scoring it as the brand's *current* wording would state something about the brand that no current receipt supports. Their history is diffed and their claims are listed in the timeline with dated receipts, which is what "rely on Wayback for those" buys. What is missing is the "and say so" half of brief Section 8: the "What we could not check" line for a robots-disallowed page does not mention that its archived copies were read instead (rework item 2).

(d) **ADR-011 compliance: yes.** Both histories belong to fictional brands on `.example` domains with no Wikidata id; every CDX row and snapshot file is marked `synthetic fixture … web.archive.org never served it`; the guard test checks reserved TLDs, the marker comment, one snapshot file per CDX row and no stray snapshot directories; the three real brands carry no hand-built history and show `skipped: Wayback unreachable (HTTP 404)` offline, which is shown, not hidden. Quillmoor's "oat drinks" claims are generic category text, not a real company's words.

(e) **Wording: compliant.** Label "Claim removed between X and Y: present in the X archived copy of the page, absent from the Y copy" and the timeline line "claim removed between 2021 and 2024" state only what two receipts show; METHODOLOGY Section 6 says explicitly that a removal is a risk signal, not a finding about why it was removed; `llm_used: false` on every Phase 4 signal, so the 50% cap is untouched. All strings live in `wording.ts` and pass the forbidden-word scan.

**Verdict: REWORK**

1. **Deterministic clock for the offline e2e run.** When `GR_OFFLINE_FIXTURES=1`, honour an env var (e.g. `GR_FIXED_NOW=2026-10-20T00:00:00Z`) for the pipeline's `now()` (and for anything else that derives the year window); ignore it outside offline mode, with a unit test proving both. Set it in `playwright.config.ts`'s `webServer.env`. Then make `tests/e2e/timeline.spec.ts` assert the literal step label `Pulling 2019–2026 snapshots` and the literal row counts, so the test fails loudly if the clock is ever not pinned. The fixture `fetchedAt` must not change.
2. **"Say so" for robots-disallowed pages (brief Section 8).** When a robots-disallowed page got a Wayback lookup, its "What we could not check" line must say what happened with the archive: archived copies read (n snapshots, years), no archived snapshot, or Wayback unreachable. One wording string in `wording.ts`, one unit test on the step (Northwind's `/stories/archive/our-footprint-2019/` is the ready-made case: disallowed, CDX `[]`), and the Phase 2 e2e for the robots-disallowed page extended to see the new wording.

Not rework (logged): newest-snapshot-vs-live-page diff → Phase 7 (ADR-017); Phase 7 criterion 7.6 now names the fictional removed-claim brand (ADR-017); archived text of robots-blocked pages stays unscored on the claims axis (ADR-016).

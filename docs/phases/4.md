# Phase 4 — Wayback snapshots, diff, retraction detector (A), timeline

Builder note, 2026-10-20.

## Built

- **`src/lib/wayback/cdx.ts`** — `cdxUrl(page, now)` builds the brief's query exactly (`url=<page, percent-encoded>&output=json&filter=statuscode:200&collapse=timestamp:4&from=<year-8>`); `parseCdx` reads the header row + data rows by column name; `pickYearly` keeps one capture per calendar year (newest of each year) for the last 8 years (2019–2026 today); `listSnapshots`; `waybackIntervalMs` (WAYBACK_RATE_LIMIT_MS can raise the spacing, never below 1000 ms); `WaybackUnavailableError` for network errors, 429, 5xx and non-JSON 200 answers. Parameters in `config/wayback.json` (`years: 8`, `maxPages: 3`, `sameClaimSimilarity: 0.8`, `contextSentences: 2`, `minIntervalMs: 1000`).
- **`snapshot.ts`** — `https://web.archive.org/web/<ts>id_/<url>`, `visibleText` on the raw page (nav/header/footer stripped as for live pages), `fetchedAt` kept from the cache. `waybackAwareTtl`: the shared `CachedFetcher` now takes a per-URL TTL; `id_` snapshots never expire, everything else keeps `GR_CACHE_TTL_HOURS`.
- **`diff.ts`** — `diffSnapshots` / `diffSentences`: `diffArrays` (package `diff@8`, added) over the Phase 3 sentence splitter's output, sentences compared after normalising case, spaces, quotes and closing punctuation ⇒ `{ removed, added, from, to }`. `similarity`: Sørensen–Dice over character bigrams of the normalised sentences.
- **`retraction.ts`** — `detectRetractions(snapshots, { brand })`: for each consecutive pair, every removed sentence that a Phase 3 rule matches (`classify`, same next-sentence and brand context) and that has no sentence ≥ 0.8 similar in the later snapshot ⇒ `Signal{ axis: 'track', kind: 'claim.removed', source_url: earlier id_ URL, snapshot_date, fetched_at, excerpt: the sentence, llm_used: false }` + a `DiffCandidate` (`classification: 'unclassified'`, context before/after in the earlier copy, nearest sentence and its similarity in the later copy) for Phase 7. Same claim removed twice (after a restore) ⇒ one signal. Builds `TimelineEntry { year, snapshot_url, claims_present, claims_removed }` per snapshot, plus `page_url`, `snapshot_date` and `previous_year` (needed to print "between X and Y" and to group by page).
- **Pipeline step** `src/lib/pipeline/steps/wayback.ts`, label `Pulling <y1>–<y2> snapshots` (`steps.wayback`), placed in the brief's order: discover → fetch current pages → **Wayback** → claim language → evidence. Targets: robots-disallowed sustainability-type pages first (brief Section 8 / the Phase 2 carry-forward: we cannot fetch them live, so we read their history), then fetched sustainability-type pages, at most 3. Uses `ctx.apiFetcher` (the cached, rate-limited fetcher without the robots guard; ADR-010: Wayback API endpoints only); brand pages still only go through `ctx.pageFetcher`. Failure handling:
  - network error / 429 / 5xx / non-JSON CDX ⇒ stop at once, `skipped: Wayback unreachable (<status>)`, keep what was found before, add a could-not-check line; the run continues;
  - CDX non-200 for **every** target ⇒ same skip (a valid CDX query never answers 404, so this is the archive not serving us); for only some targets ⇒ could-not-check line per page;
  - `[]` ⇒ could-not-check "no archived snapshot from 2019–2026"; one snapshot only ⇒ could-not-check "no change over time could be checked"; a 404 snapshot ⇒ a `skipped: HTTP 404 for <id_ url>` progress line.
- **Persistence and UI** — new table `run_timeline (run_id PK, data JSON)` + `RunTimelineRepo`; `RunView.timeline`; a minimal "Timeline of archived claims" section on `/analyse/[runId]` (the placeholder report page until Phase 8): one list per page, one row per archived copy linking to its `id_` URL, claim count, and "claim removed between 2021 and 2024: “…”" lines. All strings in `wording.ts`; forbidden-word test green.
- **Rate limit wiring** — `buildRateLimiter(env)` in `services.ts` (web.archive.org minimum from `waybackIntervalMs`), used by `buildFetcher`.
- **Fixtures (ADR-011)** — no real snapshot could be recorded (below), so both histories are for **fictional** brands on `.example` domains, every file marked `synthetic fixture … web.archive.org never served it`:
  - `northwind/` `/our-footprint/`: 2020, 2021, 2024, 2025 copies; "Every Northwind jacket is climate neutral…" present in 2020–2021, absent in 2024–2025; rest largely unchanged (yearly figures, a nav item, promo bar). Empty CDX answers for the other three pages the step looks up (including the robots-disallowed archive page).
  - new fictional `quillmoor/` (Quillmoor Foods Ltd., `www.quillmoor-foods.example`, food, no Wikidata id): robots, home, `/sustainability`, and a 2020/2022 table layout → 2025 card redesign of the same three claims (sentence → heading, "We're" → "We are", reordered).
  - `manifest.json` gains `wayback: { "<page url>": "<page-slug>" }`; `loadBrandFixtures` serves `cdx/<page-slug>.json` and `snapshots/<page-slug>/<YYYYMMDD>.html` for the matching web.archive.org URLs, so offline mode and the tests go through the real CDX/`id_` code path.
  - Guard test extended: Wayback page URLs and CDX `original`s of synthetic fixtures are on reserved TLDs; every CDX row has its snapshot file; a real fixture's snapshot must start with `<!-- real capture: `, a synthetic one with `<!-- synthetic fixture`; no stray snapshot directories.
- **Docs** — METHODOLOGY Section 6 (archived claims: pages, snapshots, diff, removal rule, signal, timeline, examples, skip path; later sections renumbered); `docs/LIMITATIONS.md` created (Wayback unreachable, fixture consequence, coverage limits); `fixtures/brands/README.md` (Quillmoor, Wayback layout and expected results); `docs/LATER.md` (diff newest snapshot vs live page; record real-brand histories).

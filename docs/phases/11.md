# Phase 11 — SBTi commitment status (track-record axis)

Builder report. Plan: `docs/PLAN.md` Phase 11; decisions ADR-026, ADR-031; source row and attribution line: `docs/SOURCES.md`.

## What was built

- **Binary bodies (11.6).** `FetchOptions.binary` makes `UndiciFetcher` and `FixtureFetcher` return `FetchResult.bytes` (and `body: ""`). `CachedFetcher` stores binary bodies as base64 with a new `fetch_cache.encoding` column (`utf8` | `base64`) and returns identical bytes from SQLite. `openDb` adds the column to older databases (`ADDED_COLUMNS` in `src/lib/db/schema.ts`).
- **`src/lib/registries/sbti.ts`.** `parseSbtiExport` (exceljs, MIT, the one new dependency) reads the export's first sheet into rows with the 12 planned fields; `date_updated` becomes an ISO date from an Excel date cell or serial (`excelSerialToIso`). Corrupt file or missing columns ⇒ `SbtiParseError`. `lookupSbti` applies the ADR-019 rule on `company_name` (scored = equal after normalisation, possible = whole word) plus ISIN/LEI equality with the Wikidata entity. `sbtiSignals` emits `sbti.commitment_removed`, `sbti.status_note` (every `status_reason` item in `neutralReasons`), `sbti.targets_validated` (near-term "Validated Targets") and `sbti.commitment_pending` ("Commitment to Set Targets" on either status). All have `llm_used: false`, receipt = export URL + fetch date, excerpt = name, both statuses, reason, date and the binding attribution line. The removal's `weight_hint` = `defaultWeightHint` × `regulatorRuling.recentMultiplier` (if `date_updated` falls within `recentYears`) × `sbti.expiredMultiplier` (if a reason is "Expired commitment"). Parsed rows are memoised per cached copy.
- **Next.** `exceljs` added to `serverExternalPackages` in `next.config.ts`; `npx next build` passes.
- **Wikidata identifiers.** `WikidataEntity` and `Candidate` gain optional `isins` (P946) and `leis` (P1278), so the confirmed entity stored with the run carries them.
- **Step `sbti`** ("Checking SBTi target status", `src/lib/pipeline/steps/sbti.ts`), after the JDP step and before repair. It fetches through the robots-guarded, cached fetcher. A throw or non-200 ⇒ `skipped: SBTi export unreachable (<status>)`. An unreadable file ⇒ `skipped: SBTi export could not be parsed`. Every run gets a snapshot coverage line. Possible matches become `Possible match, not scored: …` lines (at most `maxPossible`, plus a count of the rest), which the report page already lists apart from receipts.
- **Config.** `config/registries.json` (`sbti.exportUrl`, `dashboardUrl`, `ttlHours` 168, `neutralReasons`, `maxPossible`). `services.ts` gives the export URL that TTL. `config/weights.json` is now **version 2**. The track axis gains `sbti.commitment_removed: 15` (the director's value) and `targets_validated`, `commitment_pending`, `status_note` at 0. New block `sbti.expiredMultiplier: 1`, the default; the director sets the final value. `confidence.axisSteps.track` gains `sbti`. The schema requires version 2.
- **Wording.** A self-contained `sbtiWording` block at the end of `src/lib/copy/wording.ts`. A removal reads "Commitment removed (as published by SBTi) for <entity>: …". `reportWording.possibleIntro` now mentions SBTi entries.
- **Recorder.** `npm run record:registries -- sbti` (`scripts/record-registries.ts`) checks robots.txt (404 on the export host), uses the project UA, TLS on and 1 req/s. It downloads the full export and saves `fixtures/sources/sbti/companies-2026-10-21.xlsx`, trimmed to 73 verbatim rows: 23 matching fixture, regulator-only and test-case names, plus 50 fixed-seed random rows. `fixtures/sources/sbti/README.md` records the full file: `last-modified` Thu, 15 Oct 2026 15:22:15 GMT, 15,816 rows, 2,325,200 bytes, sha256 `80e806c2…0e102`. `fixtures/sources/sbti/manifest.json` serves the file offline. `loadSourceFixtures` now also reads per-source `fixtures/sources/<dir>/manifest.json` files, so the shared manifest was not edited.
- **Docs.** METHODOLOGY Section 7 regenerated (version 2) and new Section 9b. LIMITATIONS has a new "SBTi target status" section and two rows in the skipped-reasons table.
- **LLM stand-in fixtures.** The summary fixtures were re-authored with `npm run author:llm`: the fixture reports changed (new step, coverage line, Fairphone signal), so their input hashes moved. Other builders who re-run it will conflict here; re-running the script after the merge fixes that.

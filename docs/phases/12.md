# Phase 12 — French repairability index (repair axis)

Built 2026-10-21 in a worktree from base `2e7dc22`. Phases 10, 11 and 13 were being built in parallel, so edits to
shared files are small and additive.

## What was built

- **`src/lib/registries/fr-repair.ts`** does the following:
  - **Listing.** It reads the data.gouv.fr dataset API (`frIndex.apiUrl` + `page_size`). It follows the API's `next_page` up to `maxPages` and de-duplicates by dataset id. It uses the robots-guarded fetcher and the v1 retry policy (3 tries, exponential backoff, `Retry-After`).
  - **Matching.** Matching follows the ADR-019 rule on the publisher (organisation name, or the owner's name). Equality ⇒ candidate. A whole word in the publisher name or the dataset title ⇒ possible: only rows whose `nom_metteur_sur_le_marche` is the brand count; if no row matches, a "Possible match, not scored" line is shown.
  - **Licence gate.** The gate reads `frIndex.openLicences`. A dataset that is not open gets one could-not-check line per publisher and licence, with up to `maxDatasetUrlsInLine` dataset URLs and "licence not specified". Its CSV is never fetched by either route.
  - **CSV parsing.** It parses the newest CSV of each open dataset. Delimiter is `;` or `,`, detected from the header; UTF-8 with or without BOM; RFC 4180 quoting; decimal commas and `dd/mm/yyyy` dates are read. Columns use the Etalab field names. Only the newest `date_calcul` row per `id_modele` is kept.
  - **Signals.** It emits one signal per dataset read: `repair.fr_index_found` (0 points), or `repair.fr_index_low` instead when the mean `note_ir` is below `lowThreshold`. Every signal has `llm_used: false`. The receipt is the CSV URL fetched, the fetch date, and an excerpt with up to 5 models (`nom_modele (categorie_produit) note_ir/10, calculated date_calcul`), the licence id and the dataset page URL. `entity_name` is the publisher, verbatim.
  - **Cache TTL.** `frRepairAwareTtl` gives data.gouv.fr URLs `frIndex.ttlHours` (24) in `src/lib/services.ts`.
- **Step `fr-repair`** ("Checking the French repairability index", `src/lib/pipeline/steps/fr-repair.ts`) runs after `repair` in `DEFAULT_STEPS`:
  - Non-durable brands: skipped with the existing not-applicable reason, and data.gouv.fr is not contacted.
  - New skipped reasons: `skipped: data.gouv.fr unreachable (<cause>)` and `skipped: repairability dataset could not be parsed (<url>)`.
  - A brand with no dataset gets a could-not-check line.
  - Any index signal removes `repair.no_repair_info_found` through the step patch (ADR-020).
- **Config.**
  - `config/repair.json` gains `frIndex` with the plan's keys plus `maxDatasetUrlsInLine` and `tabularCsvUrl` (see C-12.1 below).
  - `config/weights.json` gains `repair.fr_index_found: 0` and `repair.fr_index_low: 30`, and `confidence.axisSteps.repair` gains `fr-repair`. `version` stays 1, because Phase 11 bumps it to 2.
- **Wording.** All new copy is in `src/lib/copy/wording.ts`, appended to `steps`, `reasons`, `couldNotCheck` and `signalLabels`. The forbidden-word tests pass on it.
- **Fixtures.** `fixtures/sources/fr-repair/` holds real captures with their own `manifest.json` and README. `npm run record:registries -- fr-repair` recorded them (`scripts/record-registries.ts` dispatches to `scripts/registries/fr-repair.ts`).
  - API pages are trimmed to the fields that are read, with the original size and sha256 in the manifest.
  - Fairphone's CSV comes through the tabular API.
  - robots.txt of both hosts is included.
  - `src/lib/fetch/source-fixtures.ts` now also loads `fixtures/sources/*/manifest.json`. The ADR-011 guard in `tests/unit/regulators/fixtures.test.ts` skips directories that have their own manifest; those directories have their own guard test.
- **Docs.**
  - METHODOLOGY Section 7 was regenerated, and Section 10 gains item 6 (what the index is, legal basis, the gate, threshold, receipts, the robots route).
  - LIMITATIONS gains a coverage note and the two new reasons.
  - LATER gains one entry: the consolidated lov2 file and subsidiaries.
  - CHALLENGES gains C-12.1.
- **Regenerated files.** The LLM summary fixtures were regenerated with `npm run author:llm`. The summary inputs changed because the new could-not-check lines and the Fairphone signal are part of them. Scores are unchanged: Mammut 12, Fairphone 3, Oatly 35, Northwind 34, Quillmoor 31.

## Deviations (`docs/CHALLENGES.md` C-12.1)

1. **`static.data.gouv.fr/robots.txt` has `Disallow: /resources`.** It is the same file as www's. Every resource CSV lives under that path, so the module asks for the resource URL through the robots guard first. When that URL is disallowed, it reads the same file from `https://tabular-api.data.gouv.fr/api/resources/<id>/data/csv/`, whose robots.txt answers 404. The receipt `source_url` is therefore `tabular-api.data.gouv.fr`. The 12.8 e2e regex also accepts that host.
2. **The Fairphone CSV has 6 rows**, not 5: 6 distinct `id_modele`, all 9.3, `date_calcul` 2025-06-25. Test 12.2 pins 6.
3. **Pagination overlaps.** The API reports 125 results, but only 115 distinct datasets appear across its two pages.

## Skipped and why

- **E2E run (12.8):** the orchestrator's instruction; the specs are written, typechecked and linted.
- **Validation re-run (12.9):** depends on Phase 10, which is not in this worktree.
- **Ground-truth brands in the recorder:** Phase 10's ground truth is not here. The recorder covers the fixture brands plus Electrolux and Bosch. The API pages are brand-independent, so matching runs offline for any brand. Another open dataset's CSV would need recording.
- **README script list:** `record:registries` is not added to README, to avoid a conflict with Phases 11 and 13. Phase 15 owns the docs sync.

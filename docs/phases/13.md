# Phase 13 — Sabin Center climate litigation adapter (track-record axis)

Built in parallel with Phases 10–12 (separate worktrees). Edits to shared files were kept small and additive:
one step in `DEFAULT_STEPS`, one `litigation` block and one points row in `config/weights.json`, one wording
object appended to `wording.ts`, one METHODOLOGY section (9c), rows appended to LIMITATIONS.

## What was built

- **`src/lib/registries/sabin.ts`**: the `CaseAdapter` (`discover`, `fetchCase`).
  - The parser reads the server-rendered `__NEXT_DATA__` of `/document/<slug>`: title, summary, filing date and
    year, status, last event and geographies.
  - The geography parser returns the families a `/geographies/<slug>` page server-renders (4 each).
  - Party parsing drops parenthesised nicknames, then splits on " v. ", " v ", " vs ", " vs. ", " et al.", ","
    and " and ".
  - `matchCase` applies the ADR-019 equality rule per party: scored or possible, never a fuzzy score.
  - `statusMultiplier` and `caseWeightHint` use the `config/weights.json` `litigation` keyword rules and the
    `regulatorRuling` recency values.
  - `caseSignal` builds the label "Case found naming <party> (<status>, filed <year>) — a filed case is not a
    ruling". The excerpt is the title, 300 characters of the summary, the status and last event as published,
    and the attribution line.
  - `isAllowedSabinUrl` allows only `/document/`, `/geographies/` and `/robots.txt` on
    `https://www.climatecasechart.com`, with no query string. Any other URL is refused before a request is made.
- **Discovery**: the P17 country page (`config/registries.json` `sabin.countrySlugs`), the US page, then the
  recorded seed index (`fixtures/sources/sabin/index.json`).
  - Listed families are fetched only when their title names the brand.
  - Seed entries are always re-fetched, and the title on the page decides the match.
  - A URL is fetched at most once; at most `maxCases` (12) case pages per run.
- **Step `sabin`** (`src/lib/pipeline/steps/sabin.ts`, "Checking the climate litigation database") runs after
  `jdp-fr` and before `repair`. `confidence.axisSteps.track` gains `"sabin"`.
  - Site unreachable or robots ⇒ `skipped: climatecasechart.com unreachable (…)` or the robots reason.
  - One case page failing ⇒ its own progress line (`case page could not be parsed (<url>)`).
  - The coverage sentence is always present, even when the step is skipped.
  - A possible match becomes a `Possible match, not scored:` line, which the report page already lists apart
    from the receipts. The intro of that section now also names litigation cases.
- **Weights** (`config/weights.json`, still version 1; Phase 11 does the bump to 2):
  - `points.track["litigation.case"] = 10`;
  - `litigation` = `baseHint` 1, `statusMultipliers` (dismissed/withdrawn/struck out ⇒ 0; pending/filed/ongoing
    ⇒ 1; decided/judgment ⇒ 1), `unknownMultiplier` 1.
  - The zod schema has the new block. METHODOLOGY Section 7 was regenerated, and `paramRows` renders the rules
    one per row.
- **Fixtures** (`fixtures/sources/sabin/`, with its own `manifest.json` and `README.md`):
  - real captures of 6 geography pages and 4 case pages, plus robots.txt;
  - the seed index;
  - 2 marked synthetic pages for Northwind (possible) and Quillmoor (dismissed), used by unit tests only.
  - `source-fixtures.ts` also loads sub-manifests (`SUB_MANIFEST_DIRS`), and the v1 ADR-011 guard skips such
    directories, which have their own guard.
  - The app's API token is never stored, and a test checks this.
- **Recorder**: `npm run record:sabin` (`scripts/record-sabin.ts`).
- **LLM fixtures**: the summary fixtures were re-authored with `npm run author:llm`, because the report input
  changed (new could-not-check lines). Scores are unchanged.
- **Docs**: METHODOLOGY 9c; LIMITATIONS (3 skip reasons, plus a "Climate litigation" section: discovery limit,
  download form not used, terms page unreadable, status words, matching, capture changes); CHALLENGES C-13a.

## Skipped and why

- **13.9 validation re-run**: Phase 10's harness (`npm run validate`) is being built in parallel and is not in
  this worktree. Re-run it after the merge.
- **`npm run test:e2e`**: not run, as instructed (parallel builders would collide on ports).
  - I extended `tests/e2e/analyse-progress.spec.ts` (the 5.9 step list now includes the new step).
  - I added `tests/e2e/litigation.spec.ts`: the progress step plus coverage line, and a receipt row linking to
    `www.climatecasechart.com`. No fixture brand is named by a case, so it stores an Oatly report copy with one
    signal built from the real TotalEnergies capture, the same pattern as `possible-match.spec.ts`.
  - The orchestrator runs both after merging.
- **13.7 pin location**: the "litigation.case < regulator.ruling" pin is in
  `tests/unit/registries/sabin-weight.test.ts`, not in `weights-v2.test.ts`, which Phase 11 creates. This avoids
  a cross-worktree conflict; it can be moved after the merge.
- **`npm run record:registries -- sabin`**: shipped as `npm run record:sabin` in its own script, because Phases
  11 and 12 create `record-registries.ts` in parallel. Wire it as the `sabin` sub-command after the merge.
- **"SE" legal suffix**: see CHALLENGES C-13a. It is handled Sabin-locally (`sabin.partyLegalSuffixes`) because
  adding it globally changes the pinned JDP search query.
- **Ground-truth membership**: TotalEnergies and BlackRock are real brands with scored real cases. Whether they
  are in Phase 10's `ground-truth.json` cannot be checked from this worktree.
- **Excerpts quote the database's summary verbatim** (first 300 characters). The recorded ones contain no
  forbidden word (tested). A future summary that uses such a word as the database's own wording would still be
  quoted, as brand-page excerpts are.

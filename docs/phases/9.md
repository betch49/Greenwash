- **`tests/unit/docs/limitations-sync.test.ts`** (criterion 9.4) renders every template in `reasons` (`src/lib/copy/wording.ts`) with its parameters as `<name>`, plus the robots.txt reason from `RobotsDisallowedError`. It asserts that each is in LIMITATIONS verbatim, in backticks. It caught one inaccuracy while I wrote it: `reasons.stepError` ("internal error (…)") is defined but never emitted, because a thrown step shows the error's own message (`src/lib/pipeline/run.ts`). LIMITATIONS says so; I left the code as it is.
- **`scripts/e2e-real.ts`** (`npm run e2e:real -- <brand> [--website …] [--prod] [--base …]`) is the real-brand end-to-end run named in PLAN Phase 9 item 3. It:
  - starts `next dev`, or `next start` with `--prod`, live with no fixtures on `test-results/real.db`;
  - drives search, confirm, analyse and report with Playwright's Chromium;
  - times three `GET /report/<id>` and a second identical search in a fresh browser context, which must redirect to the same report id;
  - writes `docs/phases/9-real-run.json` (`--prod`) or `9-real-run-dev.json`.

  It exits 1 if the re-serve is missing or takes ≥ 1 s.
- **`scripts/smoke.sh`** (criterion 9.1, for the director): `npm ci && npm run build`, then `npm run dev` offline must answer `/` with 200 within 30 s, and its output must contain no error.
- **`signals` table decision: kept and documented, not removed.** PLAN Phase 1 deliverable 2 names the table, and removing it would change a planned deliverable. Nothing reads or writes it, because signals live in `ReportV1` (`reports.data`). `src/lib/db/schema.ts` now says so above the table, and LIMITATIONS "Operations" does too. The director may rule otherwise; a drop is a 3-line change (Drizzle table, bootstrap SQL, schema test list).

## Real-brand end to end (PLAN Phase 9 item 3; brief Section 10)

**With a key: deferred: no API key.** `ANTHROPIC_API_KEY` is absent in this environment, so the AI steps could not be run against the real API.

**Without a key, live, no fixtures: done, Fairphone, 2026-10-21.** The network allowed it. fairphone.com, Wikidata (after 429 waits), ASA, JDP and iFixit all answered; web.archive.org did not.

Command: `npm run build && npm run e2e:real -- fairphone --website https://www.fairphone.com --prod`. `--website` was not needed, because Wikidata auto-proceeded to the Fairphone entity. Output: `docs/phases/9-real-run.json`.

| | Production server (`next start`) | Dev server (`next dev`) |
|---|---|---|
| run id / report id | `bd9f41d2-1a7c-44f1-99c1-5aee5d58b469` / `a05ea12c-5f68-451b-8077-5992e3f044c8` | `c28d3566-…` / `c572e36b-…` (`9-real-run-dev.json`) |
| search → /analyse (Wikidata, with 429 waits) | 28.4 s | 29.0 s |
| pipeline run | 52.3 s | 56.4 s |
| score / label / confidence / ai_share | 3 / low / 70% / 0 | same |
| signals / sources | 24 / 2 | same |
| axes | claims scored 10 (14 signals), evidence scored 0 (report found), track missing (no archive, no ruling), repair scored 0 (9 protective) | same |
| skipped | Wayback unreachable (`read ECONNRESET`); 3 × LLM unavailable (no API key) | Wayback unreachable (connect timeout) |
| `GET /report/<id>` ×3 | **45, 33, 27 ms**, `x-gr-served-from: cache` | 467, 208, 164 ms |
| second identical search → same report id | **100 ms** (browser, incl. page load), same id: yes | 2151 ms (browser); server `/confirm` 307 in 1382 ms |

Also measured with curl on `next start` against the dev run's database: `/confirm?q=fairphone` 307 to the stored report in 15–78 ms, `/report/<id>` 19–83 ms, JSON export 16 ms, and the full search-to-report with redirects followed in 34 ms.

**Cache result: served from cache in < 1 s on the production server.** On `next dev` the re-serve took over 1 s, because of dev-mode route handling; nothing was re-run, and the report id was the same. LIMITATIONS records this.

The live score (3) equals the pinned offline Fairphone fixture score (`tests/unit/score/fixtures.test.ts`, 3), so the real captures still match the live site on what the rules see.

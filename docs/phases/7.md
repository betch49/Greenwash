# Phase 7 — LLM layer: claim extraction, diff classification, summary (mocked; real client wired)

Builder note, 2026-10-21.

## What was built

**Client layer (`src/lib/llm/`).**
- `client.ts`: `LLMClient { kind, unavailable, call({name, instructions, input, schema}) → {output, used_fixture} }`. The client returns the raw output; each task validates it item by item (7.1 needs item-wise dropping, which a `→ T` signature cannot express). Shared `SYSTEM_PROMPT`: use only the text inside `<input>`, never reference or invent a source, mention only allowed URLs, signals not verdicts, answer with the tool. `stableStringify` + `fixtureFileName` = `<name>-<sha1(input).slice(0,12)>.json`. `LLMCallLog {name, used_fixture, status}`.
- `anthropic.ts`: official `@anthropic-ai/sdk` (0.137.0), `client.beta.messages.create`, one `strict: true` tool whose `input_schema` is `z.toJSONSchema(schema)` (strict objects ⇒ `additionalProperties: false`), `tool_choice: auto` + `disable_parallel_tool_use` (forced tool choice is rejected by current models), `output_config.effort` from config, server-side refusal fallbacks (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`), refusal or API error ⇒ `LLMError`. Temperature 0 only for models in `temperatureModels` (C-5).
- `config.ts` + `config/llm.json`: model `claude-sonnet-5-5` (override `GR_LLM_MODEL`), max tokens, effort `low`, limits (`extract.maxPages` 3, `maxChars` 30,000, `maxClaims` 40; `classify.maxCandidates` 20; `summary.maxWords` 120), fixtures dir.
- `mock.ts`: `MockLLM` over `fixtures/llm/`; missing file ⇒ `output: undefined` (each task's empty result), never a throw, path recorded in `missing`; with a recorder (`GR_RECORD_LLM=1` + key) a missing fixture is fetched and written.
- `select.ts` (7.7): `GR_OFFLINE_FIXTURES=1` ⇒ MockLLM (recorder when `GR_RECORD_LLM=1` and a key); key ⇒ AnthropicLLM; neither ⇒ MockLLM marked unavailable "no API key". `services.ts` holds the selected client; `startAnalysis` passes it to the pipeline.
- `validate.ts`: `validateItems` (payload must be exactly `{<key>: [...]}`; bad items dropped with a reason), `validateObject`, `urlsIn`, `wordCount`.

**Tasks.**
- `extract.ts`: input `{page_url, text (≤ maxChars), allowed_urls}`; output `{claims: {sentence, kind_hint}[]}`. Kept only if verbatim (whitespace-insensitive) in the page text, a Phase 3 rule matches it **with the page's own next-sentence and brand context** (located among the page's sentences), and no rule-found sentence overlaps it (containment either way). Then: new signal, same kinds/labels/substantiation as the page scan, `source_url` = the page, `llm_used: true`, id `llm-claim-…`. Overlap ⇒ `confirmed`, no signal (deterministic wins). Not added to ClaimStats (Phase 6 carry-forward: counted once, on top of the rate, visible in `ai_share`).
- `classify-diff.ts`: input = removed sentence + context from both copies + capture dates + `is_live_page` (no URL); output `{classification}`. `applyClassification`: redesign/moved ⇒ drop; claim_removed ⇒ keep, `llm_used: true`; unsure ⇒ keep, `llm_used: true`, `weight_hint × llm.unsureWeightMultiplier` (0.5, new key in `config/weights.json`, schema ≤ 1); no/invalid answer ⇒ unchanged. The cap rule is written out in METHODOLOGY 12.2.
- `summary.ts`: input = a stable projection of `ReportV1` (no run id, times or fetch dates) + `allowed_urls` (pages, signal receipts, timeline snapshot URLs). Accepted only if every URL in the text and in `cited_urls` is allowed, `passesWordingFilter`, ≤ 120 words; else "Summary unavailable".

**Pipeline wiring.** Steps `llm-extract` ("Proposing candidate claims (AI)") and `llm-classify` ("Classifying archived changes (AI)") after the claim engine, before evidence (brief Section 5 order); summary after scoring ("Writing the plain-English summary (AI)"), then the report is re-validated with `summary?`, `llm_calls[]` and the final `skipped[]`. Each step: `skipped: LLM unavailable (<why>)` (+ one could-not-check line), per-call `skipped: … AI output rejected (…)` / `AI call failed (…)` lines, never a throw. `StepResult.patch {remove, replace}` lets the classifier drop or replace earlier signals by id (never add); a drop also removes the line from the timeline's `claims_removed`. `PipelineDeps.llm` (absent ⇒ "no LLM client configured"). `ReportV1` gains `summary?`, `llm_calls` (default `[]`), `timeline[].live?`; `archived_snapshots` for confidence counts archived rows only.

**ADR-017 live diff (deliverable 8 / 7.8).** `livePageSnapshot()` in the Wayback step: for a target page fetched live with ≥ 1 archived copy, the live text is appended (year = run year, `snapshotUrl` = page URL, `date` = fetch date, `live: true`); `detectRetractions` always sorts it last. Removal label "Claim removed between <year> and the current page: present in the <year> archived copy, absent from the page as fetched on <date>", receipt = the newest archived copy's `id_` URL and capture date, `DiffCandidate.to.live`. Robots-disallowed pages: no live text, no comparison. The "only one archived snapshot" could-not-check line is now written only when there is no live page to compare with. `docs/LATER.md` row updated (real-brand recordings half kept).

**Fixtures.** Northwind's 2025 `/our-footprint/` snapshot gains one sentence the live page lacks ("Our dyes are eco-friendly and kind to rivers."), marked in its header comment. `fixtures/llm/` (21 files) for Mammut, Fairphone, Oatly, Northwind, Quillmoor: **hand-authored stand-ins** written by `npm run author:llm` (`scripts/author-llm-fixtures.ts`), because no API key exists here; each file's `source` says so. Extract = rule-matched page sentences + up to two topical non-claims (which the rules must drop); classify = Northwind's 2021→2024 removal `claim_removed`, its 2025→live removal `unsure`; summary = a template over the report's receipts citing one fetched URL.

**UI (placeholder report on /analyse).** Summary paragraph with an AI note, or "Summary unavailable"; the timeline renders the live row ("current page (fetched <date>)", `data-live`) and "claim removed between <year> and the current page".

## Skipped / deviations, and why

- **No real API call.** `ANTHROPIC_API_KEY` is absent; the Anthropic client is tested with a stubbed SDK only, and the fixtures are hand-authored stand-ins (labelled). Re-record with `GR_OFFLINE_FIXTURES=1 GR_RECORD_LLM=1 ANTHROPIC_API_KEY=…` after deleting `fixtures/llm/` (LATER).
- **Temperature 0 not sent to the default model** (C-5): current models reject sampling parameters; configurable via `temperatureModels`.
- **`call()` returns the raw output, not `T`**: item-wise dropping (7.1) needs the raw payload; each task validates with its zod schema.
- **classify-diff is not exercised for the three real brands**: they have no recorded archive history, so there is no removal to classify (the step shows "skipped: no removed claim to classify"). Northwind and Quillmoor exercise it.
- **E2E summary for URL-fallback runs** is "Summary unavailable": the run's brand is the typed query, so the summary input (and hash) differs from the recorded one. Shown honestly; Phase 8 may record those inputs too.
- **No SQLite cache for LLM answers** (LATER).

**Verified by running:** `npm run lint` (clean), `npm run typecheck` (clean), `npm test` (55 files, 384 passed), `npm run test:e2e` (23 passed, offline, `GR_OFFLINE_FIXTURES=1`). No skipped tests.

**Criteria 7.1–7.8:** each has the named test and it passes; I read the sources behind them.
- 7.1 `validate.ts` drops items with extra fields / wrong types item-wise and rejects a non-`{claims: [...]}` payload as a whole; a corrupt fixture becomes `output: null` ⇒ rejected, never a throw.
- 7.2 `applyExtraction` sets `source_url: page.url` unconditionally; the output schema has no URL field; a proposal must be a whitespace-insensitive verbatim substring and the Phase 3 rules must match it (with page context); a rule-found overlap keeps the deterministic signal (`llm_used: false`).
- 7.3 `applyClassification`: redesign/moved ⇒ drop (signal and timeline line), claim_removed ⇒ keep `llm_used: true`, unsure ⇒ `weight_hint × llm.unsureWeightMultiplier` (0.5, schema ≤ 1). The classifier can only keep, halve or drop; it can never add a removal, and no LLM number enters the score (brief Section 8).
- 7.4 `checkSummary`: every URL in text or `cited_urls` must be in the fetched allow-list, forbidden-word filter (ADR-008), ≤ 120 words; otherwise "Summary unavailable".
- 7.5 / 7.7 selection matrix as specified; no-key path shows `skipped: LLM unavailable (no API key)` plus a could-not-check line.
- 7.6 Mammut, Fairphone, Oatly `ai_share` 0; Northwind 9/34 ≈ 0.265 (> 0, ≤ 0.5) with the two removals AI-assisted. `tests/unit/llm/ai-share-fixtures.test.ts` pins it.
- 7.8 live page as last element, label "claim removed between <year> and the current page", receipt = newest archived `id_` URL; robots-disallowed pages get no live comparison; the live row is marked in the timeline. Northwind's rule-only score 31 → 37 is the expected consequence of a second detected removal and is re-pinned with a comment.

**Rulings** (recorded as ADR-021 in `docs/DECISIONS.md`):
1. **C-5 accepted.** I verified the builder's claim against the current Anthropic API reference: Claude Sonnet 5.5, Opus 5.5 and Haiku 5.5 return HTTP 400 for non-default `temperature`/`top_p`/`top_k` and for forced `tool_choice` (`any`/`tool`); Haiku 4.5, Sonnet 4.6 and Opus 4.6 accept `temperature`. `config/llm.json` `temperatureModels` lists exactly those three. `temperature: 0` stays in the config and is sent whenever the model accepts it; `tool_choice: auto` + `disable_parallel_tool_use` + a `strict: true` tool with `additionalProperties: false` is the documented replacement for forced tool use. The brief's intent (no invented output, reproducible tests) is met by the strict schema, item-wise validation and recorded fixtures. Choosing an older model only to satisfy the parameter would be the worse deviation.
2. **Hand-authored LLM fixtures are acceptable under ADR-011.** ADR-011 forbids invented receipts about real brands. These fixtures produce none: an extract stand-in can only propose sentences that are verbatim in the real captured page and that the rule engine accepts; the summary stand-ins quote only the report's own receipts and cite only fetched URLs; classify stand-ins apply to the fictional Northwind only. Every file's `source` says "hand-authored stand-in, not model output" (enforced by test), `docs/LIMITATIONS.md` says so, and the brief itself allows "deferred: no API key". Condition: they must be replaced by recorded answers (`GR_RECORD_LLM=1`) the moment a key is available; `docs/LATER.md` carries that.
3. **LLM answers need not be cached in SQLite in v1.** Brief Section 1's cache rule targets external *fetches* (robots, rate limits, re-serving a known brand's report in < 1 s). Re-serving is satisfied by the stored `ReportV1`; an LLM call is not a page fetch and its answer is not a receipt. Stays in `docs/LATER.md`.
4. **"Summary unavailable" on the URL-fallback e2e run is not a defect:** the summary input legitimately differs (brand = typed query) and the page says so honestly. Phase 8 carry-forward: the Phase 8 builder must author/record the summary fixture for the Northwind URL-fallback input so the full offline flow shows a summary on the report page, and the final review must list Section 10's real-brand check as "deferred: no API key" if still absent.

**Carry-forwards for Phase 8 (not defects):** (a) the item above; (b) the report UI must render `summary` with its AI note, "Summary unavailable", the live timeline row, and the `llm_calls` log in the JSON export; (c) `call()` returning the raw output instead of `T` is accepted as a plan-text correction (criterion 7.1 needs the raw payload).

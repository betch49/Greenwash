# Phase 10 — Validation set and harness

Builder note, 2026-10-21. Plan: `docs/PLAN.md` Phase 10; sources: `docs/SOURCES.md`; decisions: ADR-025 (labels evaluation-only), ADR-029.

## Built

1. **Ground truth** `fixtures/validation/ground-truth.json`: **22 flagged, 20 well-rated, 6 contested** (48 entries). Every citation was fetched from the build container by the new recorder `npm run record:validation` (`scripts/record-validation.ts`): robots.txt checked before every request (fail closed), 1 request per second per host, the app's User-Agent, normal TLS verification through the proxy CA. Copies are stored under `fixtures/validation/citations/`. Every "why" line is **generated from the fetched content** (case-article headings, the SBTi row's status fields, the Net Zero Tracker record's fields, the ruling's title, date and outcome). The only hand-written text is the one-line topic of the 4 ASA/JDP rulings, written after reading the stored ruling. The recorder also computes the group from the verified citations only. All citations are `verified_from_container: true`. Nothing comes from NewClimate (403) or B Corp (blocked): those citations would have had to come from memory. Input: `fixtures/validation/candidates.json`. Method, exclusions and bias: `fixtures/validation/README.md`.
   - Flag sources: Changing Markets brand pages (19 brands), SBTi "Commitment Removed" rows (6), ASA rulings (Oatly, Shell), JDP decisions (TotalEnergies).
   - Well-rated = no flag (not in the Changing Markets index, no SBTi removal, no ASA or JDP ruling naming the brand, all recorded as `checks`) plus two markers: SBTi validated near-term and net-zero targets, and a Net Zero Tracker interim target with a published plan. Dropped by the checks: BT Group and Vodafone (ASA rulings on any topic rule the label out), and Orange (JDP lists decisions without an advertiser name, which cannot be ruled out).
   - Register key for greenwash.com is `changing_markets`: the forbidden-word scan (3.6) flags the string "greenwash.com" in `src/` literals and in METHODOLOGY.
2. **`src/lib/validation/`**: `ground-truth.ts` (zod schema, loader, `label_use === "evaluation_only"`, SOURCES.md rules as `groundTruthProblems`), `stats.ts` (Mann–Whitney AUC with half credit for ties, mean/median and their differences, tie-averaged ranks, Spearman), `harness.ts` (one brand → the app's run path → report, step statuses, skipped reasons; never throws), `report.ts` (results schema, leakage, `RESULTS.md` rendering with a history of every results file).
   - **Run path.** `src/lib/pipeline/start.ts` now exports `launchRun(services, run)`, the function behind `startAnalysis` (behaviour unchanged). The harness creates a run row exactly like the confirm screen does (brand, website, Wikidata entity) and calls it. The label never reaches the pipeline; a test checks the stored run rows.
   - **Entering a brand.** Offline: the fixture's recorded entity. Live: the app's Wikidata disambiguation (candidate with the entry's Wikidata id, else the confident match), else the URL fallback with the entry's website.
   - **What counts as a report.** A run that produced a report from at least one fetched page. A run that fails, or that fetched no page (robots unreadable, bot wall), counts as `failed` with its reason and stays out of the AUC sample. This keeps "the site blocked us" from showing up as "low risk". It is my reading of "N of M brands produced a report". The director may rule otherwise.
3. **`npm run validate -- [--mode offline|live] [--brands a,b] [--out dir] [--tag name] [--db path]`** (`scripts/validate.ts`).
   - Offline uses `GR_OFFLINE_FIXTURES=1` services, a throw-away database and a pinned clock (`GR_FIXED_NOW`, default 2026-10-21T12:00Z).
   - Live uses the app's live services with the fetch cache in `data/validation.db` (gitignored).
   - Results carry `mode`, `n_flagged`, `n_well_rated` (selected), `n_flagged_ran`, `n_well_rated_ran`, `n_ran`, `n_failed`, `n_not_run`, `commit`, `commit_dirty`, `weights_version`, the LLM used, notes and per-brand coverage. They include "Partial run: N of M brands produced a report." when it applies.
   - The script writes only `docs/validation/results-<date>-<mode>[-<tag>].json` and `docs/validation/RESULTS.md`.
   - **Later phases:** pass `--tag phase11` (and so on) so a same-day re-run does not overwrite the Phase 10 file. RESULTS.md keeps every file in its history table.
4. **Offline subset:** new real captures of innocent and TotalEnergies (flagged), and Signify and Essity (well-rated). Each was recorded with `record:wikidata`, `record:brand` and `record:sources -- --add …`. The new `--add` mode keeps every existing source capture byte-identical: already-recorded URLs are served from file and the manifest diff only adds lines. Oatly (v1) is the fifth subset brand. The fixture READMEs are updated. `tests/unit/fetch/brand-fixtures.test.ts` now pins the list of real brands (v1 three plus these four) instead of "exactly three".
5. **Live run** from the container: see the result below and `docs/validation/RESULTS.md`.
6. **METHODOLOGY Section 13** "Validation (evaluation only)". This is an additive section at the end of the file.
7. **docs/CHALLENGES.md C-6:** the regulator step scores rulings on any topic. Seen on TotalEnergies' "Heures Eco" price decision. This is an observation only and nothing was changed.

## Result

- **Offline** (`results-2026-10-21-offline.json`): 5 of 48 brands ran (3 flagged, 2 well-rated; every brand with a fixture). **AUC 0.67**. Mean score difference +5.8 (flagged 34.3, well-rated 28.5). Spearman words–score −0.10, claim matches–score +0.30. Leakage: 3 of 22 flagged entries are flagged only by ASA/JDP, and 2 of the 3 flagged brands that ran. With n = 3 and n = 2 this figure is **indicative only**, and RESULTS.md says so.
- **Live**: (`results-2026-10-21-live.json`, labelled partial): 23 of 48 entries selected (17 flagged, 6 well-rated); **15 produced a report** (10 flagged, 5 well-rated), **8 failed** because no page could be fetched (bot walls or 403 at shell.com, unilever.com, asda.com, primark.com, www2.hm.com and teliacompany.com; HTTP/2 resets on robots.txt at uniqlo.com and asos.com). The run used no LLM and no Wayback. Wikidata answered 429 for some queries, so Signify, Schneider Electric and Siemens went through the URL fallback. **AUC 0.34** (mean difference +0.6, median −4.0); per-axis: claims 0.20, evidence 0.60, repair 0.64, track n/a. Spearman words–score −0.17, claim matches–score +0.26. Leakage: 2 of the 10 flagged brands that ran. With 5 well-rated reports this meets the "at least 5 per group" bar only just. The rule-based score does **not** separate the groups on this live sample: the claims axis is reversed, which is consistent with the "saying less scores better" concern of ADR-030.

## Skipped, and why

- **Full live run of all 48 brands.** It ran at about 75 s per brand (robots, pages at 1 request/s, ASA, JDP, iFixit, and Wayback timing out). The first attempt was stopped after 17 brands when the orchestrator asked to cap live recording. The committed live run covers a `--brands` subset: 17 flagged and 6 well-rated. The other entries are stated as not run in the results file. This is the pre-authorised cut "Phase 10 live run (keep offline harness, state it)", applied partially.
- **Live AI steps.** There is no `ANTHROPIC_API_KEY` in the container, so they show "LLM unavailable (no API key)". The live scores are rule-based only.
- **Wayback.** web.archive.org resets connections from the container, so the step is skipped on every live brand: no archived-claim data. The offline fixtures for the real brands have no recorded CDX either (v1 limitation).
- **SBTi export hash.** The recorder now also writes the export's SHA-256 and row count into each SBTi excerpt. I did not re-run the recorder after that change, because it would have re-fetched about 150 pages while the live run was using the same hosts. The committed excerpts carry the export URL, `last-modified` and fetch time. The next `record:validation` run adds the hash.
- **README / LIMITATIONS.** These are Phase 15 deliverables and were left alone, apart from the additive METHODOLOGY section. No new `skipped:` reason template was added, so the 9.4 sync test is unaffected.
